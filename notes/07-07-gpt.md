## Remember these 3 things

1. **Training is parallel, generation is serial.**
   - Training: one forward pass over N tokens gives N−1 next-token predictions at once. The causal mask stops each position from seeing its own answer.
   - Generation: one full forward pass per new token, each waiting on the last. 500 tokens = 500 sequential steps. This is the "autoregressive tax" and the main cause of LLM latency.
2. **The loss is shift-by-one cross-entropy.**
   - `[t1, t2, t3, t4]` → inputs `[t1, t2, t3]`, targets `[t2, t3, t4]`. Average −log p(target) over positions.
   - Pre-training, SFT and LoRA fine-tuning all use this loss. Only the data changes.
   - **Hugging Face shifts `labels` for you.** Pass `labels=input_ids` unshifted. Shift yourself as well and you silently train on "predict two tokens ahead" (loss 8.69 instead of 4.64 in my lab).
3. **Decoding choices are product choices.**
   - Greedy is deterministic but **loops** (real GPT-2 repeated one sentence three times in 40 tokens).
   - Temperature reshapes the distribution. top-k, top-p and min-p cut off the tail.
   - **min-p adapts to the peak and top-p doesn't:** on "The capital of France is", top-p 0.9 kept **1,503** tokens while min-p 0.1 kept **16**.

## In plain English

A GPT is autocomplete that's been read the whole internet. Give it some text and it hands back a probability for **every** token in the vocabulary as the next one. Pick one, stick it on the end, and ask again. That loop is all "generation" is.

**Why training is cheap and generation is slow.** It's like a fill-in-the-next-word worksheet:
- **Training** is marking a worksheet where every line is already filled in correctly. You can check all the lines at once, as long as each line can't peek at the line below it. The causal mask is the sheet of paper covering everything below.
- **Generation** is writing a new worksheet where each line depends on what you just wrote. You can't write line 5 before line 4, however many people (GPU cores) you have.

**Teacher forcing:** during training the model always sees the *true* previous tokens, not its own guesses. That's what makes the parallel training pass possible.

**The model is just the parts from earlier lessons, stacked:**

```text
token ids
  → E[ids] + P[positions]               embeddings + learned positions (attention is order-blind, 07/02)
  → block × L:  x = x + attn(LN(x))     read from earlier tokens, ADD to the residual stream
                x = x + mlp(LN(x))      think per token, ADD to the residual stream
  → LN, then x @ E.T                    logits over the vocabulary (tied embeddings)
```

The `x = x + ...` is the residual highway from 03/03: the gradient flows back through it at ×1, which is why 100-layer models can train at all.

## Worked example 1: shift-by-one

```text
ids      = [5, 9, 2, 7, 3, 8]
inputs   = [5, 9, 2, 7, 3]
targets  = [9, 2, 7, 3, 8]
```

| Row of logits | Has seen | Must predict |
|---------------|----------|--------------|
| 0 | 5 | 9 |
| 1 | 5, 9 | 2 |
| 4 | 5, 9, 2, 7, 3 | 8 |

If the model gives the right target p = 0.6 at one position, that position's loss is −ln 0.6 = **0.511**. The sequence loss is the average across rows.

**Sanity numbers:**
- Untrained model: loss ≈ **ln V** (uniform guessing, 01/09). My toy V = 50: 3.904 vs ln 50 = 3.912.
- Trained GPT-2 on one English sentence: loss **4.64**, perplexity e^4.64 ≈ **103**. Compare with **50,257** for uniform guessing (ln = 10.82).

## Worked example 3: the three filters

```text
A (peaked) = [0.90, 0.05, 0.03, 0.01, 0.01]    cumulative [0.90, 0.95, 0.98, 0.99, 1.00]
B (flat)   = [0.22, 0.21, 0.20, 0.19, 0.18]    cumulative [0.22, 0.43, 0.63, 0.82, 1.00]
```

| Filter | Rule | A keeps | B keeps |
|--------|------|---------|---------|
| top-k = 2 | the 2 biggest | 2 → [0.947, 0.053] | 2 |
| top-p = 0.9 | smallest set with cumulative ≥ 0.9 | **1** (0.90 already reaches it) | **5** |
| min-p = 0.1 | p ≥ 0.1 × max | threshold 0.09 → **1** | threshold 0.022 → **5** |

- top-k is blind to shape: it keeps 2 on the confident A (adding junk) and only 2 on the flat B (cutting good options).
- top-p and min-p both adapt here. **On real GPT-2 they don't agree:** the tail of 50,000 tiny tokens adds up, so top-p 0.9 had to take 1,503 tokens to reach 90%, while min-p kept 16.
- To shrink what top-p keeps, **lower** the temperature first. That sharpens the distribution, so 90% of the mass fits in fewer tokens. Temperature is applied *before* the filter (both in my code and in HF).

## Formulas

| Formula | Symbols |
|---------|---------|
| loss = −(1/(N−1)) Σᵢ log softmax(zᵢ)[tᵢ₊₁] | zᵢ = logits row i, tᵢ₊₁ = the true next token, N = sequence length |
| perplexity = e^loss | "effectively choosing between this many tokens" |
| p = softmax(z / T) | T = temperature; T < 1 sharpens, T > 1 flattens, T → 0 is argmax |
| min-p keeps tokens with p ≥ min_p · max(p) | the threshold moves with the peak |
| top-p keeps the smallest prefix (sorted descending) with Σ p ≥ top_p | fixed mass, not a fixed count |
| logits = LN(x) · Eᵀ | E = the token embedding matrix, reused as the output layer ("tied") |

## My code (labs/07-07-gpt/my_gpt.py)

```python
def gpt_logits(token_ids, params):
    n = len(token_ids)
    x = params["E"][token_ids] + params["P"][np.arange(n)]   # what each token is + where it is
    for block in params["blocks"]:
        x = decoder_block(x, block)                          # x + attn(LN x), then x + mlp(LN x)
    x = layer_norm(x)                                        # final LN before the head (pre-norm style)
    return x @ params["E"].T                                 # tied embeddings: (n, vocab)
```

```python
def top_p_filter(probs, p):
    order = np.argsort(probs)[::-1]                          # most likely first
    cumulative = np.cumsum(probs[order])
    n_keep = np.searchsorted(cumulative, p) + 1              # first index reaching p, as a count
    ...                                                      # zero the rest, renormalise
```

```python
def generate(prompt_ids, params, n_new, rng, temperature=1.0, filt=None):
    ids = list(prompt_ids)
    for _ in range(n_new):
        last = gpt_logits(ids, params)[-1]                   # ONLY the last row predicts the next token
        if temperature == 0:
            nxt = int(np.argmax(last))                       # greedy; avoids dividing by 0
        else:
            probs = softmax(last / temperature)              # temperature BEFORE the filter
            if filt: probs = filt(probs)
            nxt = rng.choice(len(probs), p=probs)
        ids.append(nxt)
    return ids
```

**Use it:** in `use_it.py`, `loss_by_hand` ran GPT-2 on `ids[:-1]` and scored against `ids[1:]`. That equals running on all ids and dropping the last row, **because of the causal mask**: row i never depends on later tokens.

**Fixes still to make:**
- `top_k_filter` with `k=0`: `argsort(probs)[-0:]` is the *whole array* (−0 == 0), so "keep 0" keeps everything. Use `argsort(probs)[::-1][:k]` or require k ≥ 1.
- `sequence_loss` loops over rows in Python; `log_softmax(logits)` already works on all rows at once.

## Where this shows up in AI engineering

- **Latency and cost.** Output tokens are serial, so they cost more time than input tokens. Long replies are slow whatever GPU you buy. The KV cache (next lesson), continuous batching and speculative decoding all exist to fight this.
- **Sampling settings in an API call.** Use temperature 0 for extraction, classification, JSON and tool calls. For creative text, use about 0.7 with min-p or top-p. Greedy can still loop, so set `max_tokens` and stop sequences.
- **Fine-tuning (Phase 11).** SFT and LoRA use exactly this loss. The classic silent bug is double-shifting the labels. A related one is forgetting to mask the prompt tokens out of the loss (labels = −100) when you only want to train on the answers.
- **Evals.** Perplexity on held-out text is the basic "did fine-tuning break the model?" check. ln V tells you the model is guessing uniformly, which means something is broken.

## Words

| Word | Meaning |
|------|---------|
| Decoder-only | A transformer with only masked self-attention + MLP blocks (no encoder, no cross-attention). GPT, Claude, Llama, Qwen. |
| Causal / autoregressive | Each token depends only on the ones before it. Generation feeds outputs back as inputs. |
| Teacher forcing | Training on the true previous tokens, not the model's own guesses. |
| Residual stream | The vector `x` that each block reads from and adds to. |
| Pre-norm | LayerNorm *before* attention / MLP inside each residual branch (GPT-2, Llama). More stable at depth. |
| Tied embeddings | Reusing E as the output layer: logits = x · Eᵀ. |
| Greedy / temperature / top-k / top-p / min-p | Decoding strategies; see worked example 3. |
| Speculative decoding | A small draft model proposes several tokens; the big model checks them in one parallel pass. 2–3× faster at the same quality. |

## Self-test

1. **A 1,024-token training sequence gives how many predictions, and why can they run in parallel?**
   <details><summary>Answer</summary>1,023, one per position that has a next token. The causal mask means position i's output can't see token i+1, so it can't cheat, and all positions can be scored in one forward pass.</details>
2. **You change only the last input token. Which logit rows change? What if you delete the mask?**
   <details><summary>Answer</summary>With the mask, only the last row changes, because earlier rows never attend to it. Without the mask, every row changes, because every position attends to every token.</details>
3. **Your untrained model's loss is 10.8 on a 50k vocabulary. Good or bad?**
   <details><summary>Answer</summary>That's ln(50,257) = 10.82, exactly uniform guessing. Fine for an untrained model. After training, it means nothing has been learned, so suspect the labels, the learning rate or the data.</details>
4. **A teammate passes `labels=ids[1:]` to an HF causal LM and gets loss 8.7 instead of 4.6. What happened?**
   <details><summary>Answer</summary>HF shifts the labels internally, so they were shifted twice and every position is scored on the token two steps ahead. Pass `labels=input_ids` unshifted.</details>
5. **top-p 0.9 keeps 1,500 tokens on a prompt. Name two fixes.**
   <details><summary>Answer</summary>Lower the temperature (it sharpens the distribution, so 90% of the mass fits in fewer tokens), or switch to min-p, whose cutoff is relative to the top token and drops a long flat tail.</details>
6. **Why is generating a 500-token reply slow even with the GPU mostly idle?**
   <details><summary>Answer</summary>Generation is autoregressive: 500 sequential forward passes, each waiting on the previous token. The KV cache cuts the work per step; speculative decoding cuts the number of sequential big-model steps.</details>
7. **Why did greedy GPT-2 repeat "The meaning of life is not the same as the meaning of death" again and again?**
   <details><summary>Answer</summary>Greedy always takes the locally most likely token. Once a phrase is in the context, repeating it becomes the most likely continuation, so it locks into a loop. Sampling (temperature + min-p) breaks the loop.</details>

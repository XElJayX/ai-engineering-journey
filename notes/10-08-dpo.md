# 10/08 DPO: Direct Preference Optimization

> RLHF needs SFT, a reward model and PPO. DPO skips the reward model and the RL: one supervised loss on (prompt, winner, loser) pairs against a frozen reference. On GPT-2 (concise > chatty), DPO at lr 5e-7 moved concise answers from 13% to 21–30%, and SimPO reached 53%. At **lr 5e-6** the loss hit 0.000 while the **winner's own log π fell** (−2.4), the loser dropped −100 nats, and the model collapsed (0% concise, 46% correct). Adding an SFT term fixed it (99%). Plain SFT on the winners got 100%.

## Remember these 3 things

1. **The DPO loss is a logistic loss on the gap between two log-ratios.**
   - `r(y) = β·[log π(y|x) − log π_ref(y|x)]`, `L = −log σ(r_w − r_l)`.
   - Step 0: π = π_ref, so the loss is **ln 2 = 0.693**.
   - The reward is *implicit*: RLHF's optimum makes reward = β·log-ratio + β·log Z, and Z cancels.
2. **The loss only sees the gap, so the winner can get LESS likely.**
   - At lr 5e-6: the winner went +0.46 → **−2.43**, the loser **−100**, and train loss 0.000.
   - Result: degenerate text ("The opposite of 'the opposite of…"), 0% concise, 46% correct.
   - Fixes: a real DPO lr (~5e-7), β, few epochs, and/or **+ an SFT/NLL term on the winner** (RPO/ORPO idea), which gave 99% with the winner at +3.2.
3. **Measure generations, not the implicit reward.**
   - Held-out preference accuracy was **100% for every run, including the collapsed one**.
   - English perplexity barely moved (27.3–28.5).
   - Only sampled outputs showed the difference. If you *have* good winners, SFT on them is a strong baseline (100%).

---

## In plain English

SFT is "copy this example answer". DPO is "of these two answers, make the first one more likely *than it was before* and the second one less likely, by more than the frozen copy of you would". It never needs a separate judge model: the change in your own probabilities *is* the score. The catch is that it only cares about the **difference**. If it can win by trashing the bad answer, it will, and if you push hard (a high lr), it trashes the good answer and everything else along with it.

## Worked example

**By hand (β = 0.1):** winner log π −35 (ref −40), loser −60 (ref −50).
- r_w = 0.1 · (−35 + 40) = **+0.5**; r_l = 0.1 · (−60 + 50) = **−1.0**
- z = 1.5 → loss = log(1 + e^−1.5) = **0.201**
- (I first divided the log-probs and took a log10 again. They're already logs: **subtract**.)

**The winner gets less likely, but the loss falls:** winner −42 (ref −40) → r_w = −0.2; loser −70 (ref −50) → r_l = −2.0 → z = 1.8 → loss 0.153 < 0.693.

## Formulas / cheat sheet

- **Implicit reward:** `r(y) = β·(log π(y|x) − log π_ref(y|x))`, where log π = **sum** over the response tokens.
- **DPO:** `L = −log σ(r_w − r_l)`; compute it as `-F.logsigmoid(z)` (stable; `log(sigmoid(−200))` = inf).
- **Gradient size:** `∂L/∂log π_w = −β·σ(−z)`. Early on σ ≈ 0.5, so the step size scales with β. At the end, a high β means less drift from π_ref.
- **SimPO:** `L = −log σ(β·(avg_w − avg_l) − γ)`: length-normalized, no reference model, γ = target margin.
- **KTO:** unpaired good/bad labels. **ORPO:** SFT + odds-ratio term in one stage. **RPO-style:** DPO + NLL on the winner.
- **Typical hyperparameters:** lr ~5e-7 (full) / ~5e-6 (LoRA), β 0.1–0.5, 1–3 epochs.
- **Memory:** DPO = 2 models (π and frozen π_ref), RLHF/PPO = 3–4. SimPO and ORPO = 1.
- **The reference subtracts the length offset** inside each ratio, but per-token changes still add up over tokens, so long answers are where margins are easiest. DPO models tend to get **longer** when winners are long.

## Mistakes to avoid

- **SFT learning rates for DPO** (5e-6 full fine-tune): loss 0, winner falls, collapse.
- **Treating train loss → 0 or reward accuracy 100% as success:** both were "perfect" on the collapsed model.
- **Dividing log-probs instead of subtracting** (a log of a ratio = a difference of logs).
- **Assuming a 50/50 dataset gives a 50/50 model:** generation = start × continue × stop.
- **`torch.log(torch.sigmoid(z))`:** −inf for very negative z. Use `logsigmoid`.
- **Leaving dropout on while comparing π to π_ref:** at step 0 the loss isn't ln 2 and the rewards are noisy.
- **Skipping the SFT-on-winners baseline** when you have good winners.

## Words

- **Preference pair:** (prompt, chosen/winner y_w, rejected/loser y_l).
- **Reference model π_ref:** a frozen SFT copy; the anchor (the KL-penalty role in RLHF).
- **Implicit reward:** β·log(π/π_ref). No separate reward model.
- **Bradley–Terry:** P(w beats l) = σ(r_w − r_l).
- **β:** the leash strength (and early-step size).
- **Likelihood displacement:** the chosen log-prob falls during DPO; mass moves to unseen outputs.
- **RLHF / PPO:** reward model + RL with a KL penalty; supports online data.
- **KTO / ORPO / SimPO:** unpaired labels / SFT + preference in one stage / no reference, length-normalized.

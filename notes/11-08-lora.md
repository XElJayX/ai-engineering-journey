## Remember these 3 things

1. **LoRA = frozen W + trainable B·A. The savings come from parameters *and* optimizer state.**
   - Per layer: `r·(d_in + d_out)` instead of `d_in·d_out`. GPT-2 `c_attn` (768 → 2304), r = 8: 24,576 vs 1.77M. All 12 layers: **294,912 = 0.24%**.
   - Init: A random, **B = 0**, so step 0 = the base model. Gradients flow through the other matrix (`∂B ∝ Ax`, `∂A ∝ Bᵀ…`), so B moves first and A from step 2. Both zero = stuck forever.
   - Forward goes through the bottleneck `(x Aᵀ) Bᵀ`: **24,576** multiply-adds per token vs **15.9M** if you build B·A every time (648×).
2. **Merge = `W + (α/r)·BA`: same size, same speed, no adapter.**
   - Merged vs unmerged logits: 2.6e-4 apart (GPU float rounding); exact match unchanged.
   - Unmerged = swappable adapters (1.12 MB vs a 475 MB model): many tasks, one base.
3. **Fine-tune for behaviour, measure the side effects.**
   - Format 40/40 for LoRA and full fine-tuning, vs 7/40 for a 3-shot prompt (+130 tokens per call).
   - Exact numbers only 26/40: GPT-2 miscopies digits (BPE). Numbers belong in retrieval, not weights.
   - **LoRA doesn't automatically prevent forgetting** (33.6 vs 31.9; my pilot gave the reverse). BA changes the output for every input. Forgetting depends on learning rate × steps, so keep a general-text check.
   - QLoRA: 4-bit **NF4** base (+1.3 perplexity) beats evenly spaced int4 (+3.0) at the same bits.

## In plain English

The pretrained model is a **printed textbook**. Full fine-tuning rewrites every page: expensive, and you can wreck chapters you didn't mean to touch. LoRA leaves the book alone and adds **sticky notes** on a few pages. The notes are tiny (a 1 MB adapter for a 475 MB book), you can swap note sets for different courses, and you can permanently print them into a new edition (merge) when you only need one.

The notes still change how every reader understands those pages, though. Sticky notes on the attention pages affect every topic, not just your task. So "the book is untouched" doesn't mean "nothing else changed": I measured English perplexity get worse.

QLoRA shrinks the printed book to 4-bit "pocket edition" print to save space. NF4 is a smarter pocket font: it spends its 16 levels where most of the weights actually are (near zero), so the text stays readable.

## Worked example

**Parameter math (GPT-2 small, r = 8, `c_attn` 768 → 2304, 12 layers):**
24,576 per layer × 12 = **294,912**; 294,912 / 124,734,720 = **0.236%** (I first said 30%: divide it out again).

**Bottleneck vs building B·A (one token):**
- (i) 768·8 + 8·2304 = **24,576**
- (ii) B·A = 2304·8·768 = 14,155,776, then x·(BA)ᵀ = 768·2304 = 1,769,472, total **15,925,248**

## Formulas / cheat sheet

- `y = W x + (α/r) · B (A x)`; A: `(r, d_in)`, B: `(d_out, r)`; same layout as `nn.Linear.weight` `(out, in)`.
- LoRA params per layer = `r·(d_in + d_out)`; full = `d_in·d_out`.
- Adam state ≈ 8 bytes × trainable params (two fp32 moments). Full 124M → 949 MB; LoRA → 2.2 MB.
- Merge: `W' = W + (α/r)·B A`.
- Common settings: r = 8–16 (format/style), 32–64 (code/reasoning); α = 2r; targets q, v (or all linear); LoRA lr ~1e-4 to 1e-3, full ~1e-5 to 5e-5.
- **Perplexity** = exp(mean cross-entropy). **Lower = better.** Damage (forgetting, quantization) makes it go **up**.
- Block quantization: per block of 64, scale = absmax (/7 for int4); NF4 = nearest of 16 normal-quantile levels.

    return self.base(x) + self.scaling * ((x @ self.A.T) @ self.B.T)  # rank-r bottleneck

## Where this shows up in AI engineering

- **Project 1:** if the model won't follow your answer format with prompting, a small LoRA (r = 8–16) on an open model fixes the format. The numbers still come from retrieval with citation checks.
- **Serving:** one base model + many adapters (vLLM / LoRAX multi-LoRA); merge for a single-task deployment.
- **Interviews:** "Explain LoRA", "Why B = 0?", "How much memory does it save, and where?" (optimizer state!), "QLoRA / NF4?", "When not to fine-tune?" (prompt → RAG → fine-tune).
- **Eval discipline:** a task metric + a forgetting metric (held-out general text or benchmark) for every fine-tune.

---

## Mistakes to avoid

- **Silent no-op injection:** a model's layers aren't `nn.Linear` (GPT-2 `Conv1D`, quantized `Linear4bit`). Assert trainable > 0 and print the replaced names.
- **Creating tensors without a device/dtype:** tests pass on CPU, then crash (or silently upcast) on the GPU.
- **Building B·A in the forward pass:** 648× the work.
- **Believing "frozen W = no forgetting":** measure it.
- **Reading perplexity backwards:** lower is better. Damage raises it.
- **Trusting fine-tuned weights for exact facts and numbers:** 26/40 exact despite 40/40 format.
- **Percent slips:** 294,912 / 124M is 0.24%, not 30%.

## Words

- **LoRA:** Low-Rank Adaptation; train B·A next to a frozen W.
- **Rank r:** the bottleneck width; the adapter's capacity.
- **α (alpha):** scales the update by α/r.
- **Target modules:** which layers get adapters (q, v, all linear).
- **Adapter:** the saved A and B (MBs); loadable on any copy of the base.
- **Merge:** fold B·A into W; no adapter left, no overhead.
- **QLoRA:** 4-bit NF4 frozen base + 16-bit LoRA, double quantization, paged optimizers.
- **NF4:** 16 levels at normal-distribution quantiles, scaled per block.
- **Catastrophic forgetting:** losing general ability while learning a task.
- **Conv1D (GPT-2):** a linear layer stored transposed, `(in, out)`.

## Self-test

1. **LoRA r = 16 on a 4096 × 4096 projection: trainable params and % of the layer?**
   <details><summary>Answer</summary>16 × (4096 + 4096) = 131,072; 131,072 / 16,777,216 = 0.78%.</details>
2. **Why B = 0 and A random, and not both zero?**
   <details><summary>Answer</summary>B = 0 makes step 0 identical to the base. ∂L/∂B ∝ (Ax) ≠ 0, so B learns; A's gradient goes through B, so it starts moving at step 2. Both zero → both gradients zero forever.</details>
3. **Where does LoRA's memory saving mostly come from in full-vs-LoRA training?**
   <details><summary>Answer</summary>Gradients and Adam state exist only for trainable params: 2.2 MB vs 949 MB for GPT-2. The frozen weights still have to be loaded (QLoRA shrinks those with 4-bit).</details>
4. **Your `inject_lora` returns [] on GPT-2. Why, and how do you catch it?**
   <details><summary>Answer</summary>GPT-2 uses Conv1D, not nn.Linear, so isinstance fails silently. Assert that the replaced list is non-empty and trainable > 0 before training.</details>
5. **LoRA got format 40/40 but exact 26/40. What does that tell you?**
   <details><summary>Answer</summary>Fine-tuning taught the behaviour; it didn't make GPT-2 reliable at copying digits across BPE boundaries. Keep facts and numbers in retrieval with checks.</details>

   <details><summary>Answer</summary>28: quantization damages the weights, and damage raises perplexity (lower is better). Real: NF4 27.7, int4 29.4.</details>
7. **Why does NF4 beat int4 at the same 4 bits?**
   <details><summary>Answer</summary>The weights are roughly normal, so most are near zero. NF4 places its 16 levels at normal quantiles (dense near 0); int4's even spacing wastes levels on rare large values.</details>

   <details><summary>Answer</summary>(a) merge: no overhead, one artifact. (b) keep separate: one base + 20 small adapters swapped per request.</details>
